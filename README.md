# Multi-cloud Alzheimer's Analytics

This project demonstrates an end-to-end Alzheimer's classification workflow:

1. Person A trains and evaluates a MobileNetV2 baseline model.
2. The integration layer exposes model results through a stable JSON contract.
3. Person B's cloud decision engine compares AWS, Azure, and GCP using workload
   size, latency, cost, and model metrics.
4. The Streamlit dashboard presents the cloud recommendation, cost comparison,
   model metrics, and the final weighted prediction.

```text
Person A model
     |  model_metrics.json
     v
Integration layer ----> Person B cloud decision engine
     |                         | cloud_recommendation.json
     +-------------------------v
                    Streamlit dashboard
```

## Current repository flow

The repository currently includes Person A's MobileNetV2 model and Person C's
integration/dashboard work. The dashboard is mock-first, so it can be run before
the cloud decision engine and shared `outputs/` files are added.

The checked-in model results are in
[`person_a_model/metrics.json`](person_a_model/metrics.json), and the trained
model, notebook, and test predictions are stored in the same directory.

## Run the demo

From the repository root:

```powershell
python -m pip install -r requirements.txt
python main.py --mock
streamlit run dashboard/app.py
```

The dashboard opens with deterministic demo data and shows:

- single-cloud versus multicloud accuracy, training time, and latency;
- AWS, Azure, and GCP cost and latency comparisons;
- the recommended provider and the reason for the recommendation; and
- a four-class prediction created by the weighted provider probabilities.

To start the dashboard from the orchestrator instead:

```powershell
python main.py --mock --launch-dashboard
```

## Live A -> B -> dashboard flow

When Person A and Person B provide their shared outputs, place them under
`outputs/` and run:

```powershell
python main.py --launch-dashboard
```

The orchestrator:

1. reads and validates `outputs/model_metrics.json`;
2. builds a workload payload containing data size, latency requirement, budget,
   model accuracy, and model latency;
3. calls `cloud_engine/decision_engine.py` with the cloud profiles;
4. validates and writes `outputs/cloud_recommendation.json`; and
5. launches the same dashboard without requiring UI changes.

The live path expects:

```text
outputs/model_metrics.json
outputs/cloud_recommendation.json       # generated by main.py
cloud_engine/cloud_profiles.json
cloud_engine/decision_engine.py
```

The model metrics contract requires these fields:

```json
{
  "model_name": "MobileNetV2",
  "accuracy": 0.7275,
  "training_time_min": 3.81,
  "inference_latency_ms": 4.56,
  "params_millions": 3.4,
  "class_labels": [
    "MildDemented",
    "ModerateDemented",
    "NonDemented",
    "VeryMildDemented"
  ]
}
```

The cloud recommendation must include `recommended_provider`. It may also
include ranked provider results, cost breakdowns, ensemble weights, provider
probabilities, and the recommendation reason. The dashboard accepts the
canonical field names and several compatible aliases.

## Project structure

```text
person_a_model/       Training notebook, MobileNetV2 model, metrics, predictions
integration/          JSON validation and provider-probability combiner
dashboard/            Streamlit dashboard
main.py               A -> B orchestration and dashboard launcher
DEMO.md               Three-minute presentation talk track
slides/SLIDES.md      Slide outline
```

`integration/ensemble.py` performs a normalized weighted average of same-shaped
provider probability arrays. It is provider-agnostic and can be tested with
Python lists or NumPy arrays.

## Important note

The dashboard's seeded comparison and final prediction are demonstration data,
not clinical predictions. Replace the mock values with measured model results
and the paper's cited comparison figures before using the project for analysis.
